# 정산·지급

정산 기준일·확정 명세·공제·보류·지급·대사·보정을 다룰 때 읽는다. 원 거래·라인·기준 기간과 실제 지급을 분리해 확인한다.

| 규칙 | 적용할 업무 |
|---|---|
| [정산 시점과 정산 기준일 처리](settlement-timing.md) | 정산 산정 기준일·대상 기간·확정일과 예정 지급일·실제 지급일을 구분하고 영업일 조정은 계약상 해당 단계에만 적용한다 |
| [정산 공제 항목 처리](settlement-deduction.md) | 정산 공제는 판매금액의 포함 항목과 부담 주체·적용 정책을 정의해 중복 차감을 막고 지급 후 반품·음수 잔액을 원 거래에 연결한다 |
| [정산 주기와 배치 처리](settlement-cycle.md) | 정산 배치는 멱등성·페이징·재시작 지점을 반드시 구현해 중복 정산과 OOM을 방지해야 한다 |
| [정산 데이터 정합성 검증](settlement-integrity.md) | 정산 완료 후 금액·건수 정합성을 검증하고 타임존을 일관되게 적용해야 한다 |
| [정산 명세서 — 시점 스냅샷으로 박제한다](settlement-statement.md) | 정산 명세서는 매번 재계산하지 말고 정산 확정 시점의 금액·요율을 불변 스냅샷으로 저장해야 한다 |
| [정산 세무 처리 — 부가세·원천징수·면세 구분](settlement-tax.md) | 정산 세무 데이터는 상품 과세 유형과 거래 당사자 관계를 분리 기록하되 실제 신고·발행·원천징수 기준은 최신 법령과 세무 검토로 확정한다 |
| [정산 보류 — 분쟁·클레임 중인 건은 지급에서 제외한다](settlement-hold.md) | 반품·클레임·분쟁에 대한 산정 제외와 지급 보류를 구분하고 계약상 사유·범위·권한·해제 시점을 추적한다 |
| [정산 지급(실이체) — 확정과 이체를 분리하고 멱등하게](settlement-payout.md) | 정산 확정과 실제 은행 이체는 상태를 분리하고, 이체 결과 확인 전에는 완료로 처리하지 않으며 이중 지급을 멱등 키로 막아야 한다 |
| [정산 구현 체크리스트](settlement-ai-pitfalls-checklist.md) | 정산 구현 완료 후 반드시 점검할 체크리스트 |
