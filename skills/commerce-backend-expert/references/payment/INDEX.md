# 결제·환불

승인·중복 요청·웹훅·미확정 결과·부분 환불을 다룰 때 읽는다. PG별 계약과 이미 구현된 상위 검증·영속 수신을 먼저 확인한다.

아래는 후보를 고르는 색인이다. 현재 작업에 맞는 규칙만 열어 적용 조건·예외·근거·검토 기록을 읽는다. 규칙 상태 active는 정확성 인증이 아니며, needs-review나 검토 기록 미기록은 확인할 한계다.

| 규칙 | 적용할 업무 |
|---|---|
| [결제 웹훅 처리 원칙](webhook-handling.md) | PG사 웹훅은 이벤트별 인증·검증과 내구성 있는 인수를 짧게 완료한 뒤 계약에 맞는 성공 응답을 반환하고 비즈니스 처리는 비동기로 수행한다 |
| [결제 상태 머신과 전이 가드](payment-status-machine.md) | 결제 상태는 유한 상태 머신으로 정의하고 각 전이에 가드 조건을 반드시 적용해야 중복 결제와 잘못된 상태 전이를 막을 수 있다 |
| [중복 결제 방어](duplicate-payment-guard.md) | 결제 버튼 중복 클릭·네트워크 재시도로 인한 이중 결제를 상태·시도 식별자·외부 거래 ID·동시성 제어로 다층 방어한다 |
| [망취소 처리 (결제 응답 불명확 상황)](network-cancellation.md) | 결제 응답을 받지 못한 상황은 미확정 상태로 기록하고 결제사업자의 조회·망취소 계약에 따라 비동기로 최종 상태를 확인한다 |
| [부분 취소 / 환불 처리](partial-refund.md) | 부분 취소는 같은 환불의 요청 내용·한도를 원자적으로 검증하고, 주문 시점의 할인 배부 정책과 반올림 규칙으로 환불액을 재현해 정산 상태와 대사한다 |
| [결제 API 멱등성 키 설계](payment-idempotency.md) | 업무키는 UUID뿐 아니라 날짜·순번 등의 고유 범위가 확보된 식별자도 가능하며, 같은 시도의 재시도에 유지하고 요청 내용을 검증한다. 외부 멱등키는 PG 계약에 맞춰 연결한다 |
| [결제 구현 체크리스트](payment-ai-pitfalls-checklist.md) | 결제 구현 완료 후 반드시 점검할 체크리스트 |
