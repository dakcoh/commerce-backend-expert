# 상품·주문·회원·배송

상품/SKU와 가격 스냅샷, 주문·배송·클레임 상태, 회원·포인트·권한 경계를 확인할 때 읽는다. 결제·재고·정산의 세부 처리는 해당 파트로 이어서 확인한다.

아래는 후보를 고르는 색인이다. 현재 작업에 맞는 규칙만 열어 적용 조건·예외·근거·검토 기록을 읽는다. 규칙 상태 active는 정확성 인증이 아니며, needs-review나 검토 기록 미기록은 확인할 한계다.

|---|---|
| [상품 카탈로그: Product, SKU, Offer를 분리한다](commerce-catalog-model.md) | 고객이 보는 상품, 실제 판매 단위, 채널별 판매 조건을 하나의 테이블로 합치지 않는다. |
| [가격과 금액: 계산 근거를 스냅샷으로 남긴다](commerce-pricing-money.md) | 표시 가격만 저장하지 말고 판매가, 할인, 배송비, 세금, 최종 결제액의 계산 근거를 보존한다. |
| [주문 생명주기: 상태 전이와 이력을 명시한다](commerce-order-lifecycle.md) | 주문 상태를 임의로 덮어쓰지 말고 허용된 전이, 전이 사유, 행위자를 기록한다. |
| [재고 가용성: 실재고, 예약, 판매 가능 수량을 구분한다](commerce-inventory-availability.md) | 선택한 재고 모델에 따라 판매 가능 수량을 정의하고 DB 조건부 차감 또는 예약의 수량 불변식을 지킨다. |
| [결제: 주문 상태와 결제 거래 원장을 분리한다](commerce-payment-ledger.md) | 결제는 성공 여부 한 칸이 아니라 승인, 매입, 취소, 환불 거래의 누적 원장이다. |

| [쿠폰과 프로모션: 혜택 계산, 배부, 사용 이력을 분리한다](commerce-promotion-allocation.md) | 할인 규칙 적용과 실제 주문 라인별 할인 배부 결과를 분리해 환불과 정산을 재현 가능하게 만든다. |
| [유통 채널과 판매자: 원장과 채널별 노출 모델을 분리한다](commerce-channel-seller-distribution.md) | 자사몰, 오픈마켓, 판매자, 창고가 늘어날 것을 고려해 채널별 상품·가격·재고 동기화를 경계로 분리한다. |
| [정산: 주문 합계가 아니라 거래 원장으로 계산한다](commerce-settlement-reconciliation.md) | 정산은 판매, 수수료, 할인 분담, 배송비, 환불을 근거 거래별로 집계하고 대사해야 한다. |
| [운영 정합성: 이벤트, 배치, 수동 조치를 추적 가능하게 만든다](commerce-operational-integrity.md) | 장애가 없다고 가정하지 말고 중복, 지연, 순서 역전, 수동 보정을 운영 가능한 형태로 설계한다. |

| [클레임과 CS: 취소, 교환, 반품, 환불을 상태와 책임으로 나눈다](commerce-claim-cs.md) | 고객 클레임은 단순 주문 취소가 아니라 요청, 승인, 회수, 검수, 환불, 정산 조정의 흐름이다. |

| [포인트와 적립금: 잔액보다 원장을 먼저 설계한다](commerce-loyalty-point-ledger.md) | 포인트는 단순 balance 컬럼이 아니라 적립, 사용, 취소, 만료, 보정 거래의 원장으로 관리한다. |
