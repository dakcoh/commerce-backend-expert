# 쿠폰·프로모션

유효성·발급 한도·할인 배부·사용 및 복원을 다룰 때 읽는다. DB만으로 충족하는 대안을 먼저 확인하고 Redis 선점·보상은 그 구조가 선택된 경우에 적용한다.

아래는 후보를 고르는 색인이다. 현재 작업에 맞는 규칙만 열어 적용 조건·예외·근거·검토 기록을 읽는다. 규칙 상태 active는 정확성 인증이 아니며, needs-review나 검토 기록 미기록은 확인할 한계다.

| 규칙 | 적용할 업무 |
|---|---|
| [쿠폰 유효성 검증 핵심 항목](coupon-validation.md) | 쿠폰 적용 전 유효 기간·사용 조건·중복 사용·발급 대상을 서버 측에서 모두 검증해야 한다 |
| [쿠폰 할인 금액 계산 — 복잡도 높은 케이스](coupon-discount-calculation.md) | 정률 할인의 cap 처리, 복수 쿠폰 적용 순서, 부분 취소 역산까지 정책을 명확히 정의해야 한다 |
| [선착순 쿠폰 발급 — 동시성 제어](coupon-issuance.md) | 선착순 쿠폰 발급은 재고 확인과 사용자 중복 선점을 하나의 원자적 연산으로 처리하고 DB 제약으로 최종 방어한다 |
| [선착순 쿠폰 발급 — Redis 선점 + DB 확정 + 보상 처리](coupon-issuance-compensation.md) | Redis 선점 + DB 확정 모델을 선택했다면 영속 attempt와 원장 대사로 중간 장애를 추적하고, DB 실패가 확정된 선점만 원자적·멱등적으로 보상한다 |
| [프로모션 규칙 엔진 설계](promotion-rules.md) | 프로모션은 우선순위·조합·버전을 명시하고, 규칙 규모와 운영 변경 요구에 따라 단순 코드·Strategy/Specification·DB 기반 규칙 엔진을 선택한다 |
| [쿠폰·프로모션 구현 체크리스트](coupon-ai-pitfalls-checklist.md) | 쿠폰/프로모션 구현 완료 후 반드시 점검할 체크리스트 |
