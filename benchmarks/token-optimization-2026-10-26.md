## 리뷰 압축을 보류한 이유

리뷰 후보는 5,669→3,910바이트로 줄였지만 최종 환불 답변 한 건에서 “후속 처리에서 혜택을 건드리지 않는지만 확인하면 됩니다”라는 표현이 나왔다. 주변 문장은 할인 유지 정책과 쿠폰 재발급·포인트 복원을 함께 언급해 권리 복원까지 제한하는 것으로 해석될 여지가 있었다.

영구 금지를 명시한 확정 오류로 판정한 것은 아니다. 다만 금액·권리 정책의 경계를 명확히 유지했다고 승인하기에는 부족해 **리뷰 스킬은 원래 5,669바이트 그대로 복원했다.** 후보와 답변을 삭제하거나 반복 실행으로 좋은 답변만 고르지 않았다. 이 결정은 구현 AI의 보수적인 채택 판단이며 독립 전문가의 판정은 아니다.

최종 비교 전체는 12사례 × 2조건, 24회다. 두 후보를 모두 압축한 실험의 총 입력은 261,605→184,201(-29.6%), 비캐시 입력은 103,269→68,361(-33.8%)였다. **이 전체 수치는 보류한 리뷰 후보까지 포함하므로 현재 채택한 구성의 절감률로 사용하지 않는다.** 사례 기준 4개는 양쪽 모두 48/48이었지만, 별도 정책 명확성 검토에서 후보 1회를 채택 보류했다. 체크리스트 점수와 채택 승인은 다르다.

## 검증기의 불필요한 탐색 수정

초기 24회에서는 총 입력 -18.2%와 함께 비캐시 입력 +2.9%가 관찰됐다. 거부된 호출은 원문 16회·후보 484회였고, 후보 웹훅 1회가 474회를 차지했다. 이 결과를 좋은 수치만 골라 최종 비교에 합산하지 않았다.

별도 진단 1회에서 모델이 제공되지 않은 `AGENTS.md`, `README.md`, 빌드 파일과 파일 목록을 찾는 것을 확인했다. 8회 실패 후 즉시 중단했으며 그때까지 보고된 사용량도 보존했다. 원인은 스킬 문서 크기만으로 설명할 수 없다. 검증 환경이 작업 폴더에 무엇이 있는지 명시하지 않았던 점을 보완했다.

- 두 조건에 같은 실제 작업 파일 목록을 전달한다. 파일이 없으면 사용자 프롬프트의 설명이 전체 업무 입력임을 명시한다. 정답·채점 기준은 전달하지 않는다.
- 이용 불가능한 조회가 8회 반복되면 해당 실행을 실패로 중단한다. 실패 샘플은 경로·종류·사유 길이를 제한해 남기며 중단 후 반복 집계하지 않는다.
- 다른 플러그인은 검증 프로세스의 feature override로 끄고 실제 설정값을 확인한다. 느린 카탈로그 조회에 의존하지 않으며 평소 사용자 설정은 바꾸지 않는다. [OpenAI Docs](https://learn.chatgpt.com/docs/config-file/config-reference)의 기능 설정과 설치된 CLI 0.153.2의 상태를 대조했다.

수정 후 웹훅 2회를 먼저 확인하고 나머지 22회를 실행했다. **최종 24회의 거부된 조회는 양쪽 모두 0회**였다. 원문 먼저/후보 먼저는 각각 6사례다. 최초 24회, 중단 진단 1회, 최종 24회를 합쳐 총 49개 작업 턴을 시작했다. 작업 턴 하나가 여러 provider 요청을 포함할 수 있으므로 실제 API 호출 수나 청구 금액과 같지 않다. CLI 사전 검사 timeout은 추론 시작 전 별도 실패다.

## 판단 품질을 확인한 범위

기본 8종 외에 혜택 정책·Lua 부분 반영·정상 환불·1인 복수 발급을 명시 선택했다. rubric v3의 사례별 네 기준과 별도의 중대한 오류 검토 조건을 실행 전에 고정했다. 두 소스·입력·기준도 사본으로 고정하고 서로 새 읽기 전용 폴더·스레드에서 실행했다.

- 정상 웹훅 2종·watchdog·정상 환불의 네 대조군에서, 제공된 계약/방어를 확정 결함으로 잘못 주장한 답변은 관찰하지 않았다.
- 환불 대조군은 실제 동기 메모리 함수를 테스트해 결함 코드가 X-1 중복을 허용하는 것과 정상 코드가 비중복 X-2를 허용하면서 UNKNOWN을 유지하는 차이를 확인했다. 실제 DB·PG 경합 시험이 아니다.
- CSS 답변은 지정한 두 값 외 HTML 본문이 원본과 정확히 같은지 검사했고 커머스 참조 비조회도 확인했다.
- 의미 판단은 구현 Codex 세션이 전체 답변을 검토했다. 키워드 존재만으로 통과시키지 않았으며, 일부 문맥상 계약 유지 판단(예: 이미 주어진 ACK 순서)은 JSON의 검토 사유에 명시했다. 독립 사람·블라인드 채점은 아니다.

## 세션 훅과 오프라인 검증

같은 플러그인 경로에서 시작 문맥은 785→620바이트(-21.0%)로 줄였다. 두 스킬 경로·적용 범위·제어 명령은 유지했고 상태 저장/격리/재개/압축 처리 로직은 바꾸지 않았다.

등록된 Node 명령과 빈 Node를 30회씩 비교한 180개 추가 관측에서 시작 훅 p50은 83.58ms, 일반 요청 79.72ms, off 82.33ms였다. 일반 요청 출력은 0바이트다. 이 PC의 직접 실행이며 이전 실행 대비 속도 개선이나 클라이언트 전체 비용을 주장하지 않는다. 모델 호출 0회이고 정상 설정도 바꾸지 않았다.

당시 로컬 `npm run check`, 테스트 50/50, 두 스킬의 Skill Creator 형식 검사, `git diff --check`가 통과했다. 원문/후보 불변 사본, 기준/입력 해시, 캐시 누락·이상값, 빈 파일 목록, 거부 호출 한도와 정상/결함 환불의 실행 차이를 확인했다. 커밋 전의 로컬 검사와 이후 CI 결과는 별개다.

## 해석의 한계와 남은 이슈

각 사례·조건 1회, 같은 고정 모델 ID의 작은 합성 표본이다. 서버 가중치·캐시·부하·내부 라우팅은 완전히 통제하지 못했다. 입력 토큰은 청구 금액이 아니며 비캐시는 총 입력에서 보고된 캐시 입력을 뺀 값이다. 통계적 품질 동등성·일반적 개발 생산성·비용 절감을 입증하지 않는다. 기존 스킬 미사용 대비 48회 실험과도 합산하지 않는다.

이는 선택된 스킬 본문·참조의 비교이며 설치부터 자동 선택·훅까지 포함한 전체 플러그인 성능은 아니다. 이 실험 당시에는 OpenClaw 실제 모델 적용과 실제 사업 환경이 미확인이라 #22·#23을 유지했다. 이후 파일 편집 시험과 사용자 요청에 따른 이슈 범위 정리는 [검증 기록 안내](../validation/README.md)에 기록한다. 이 보고서의 수치를 실제 PG·회사 정책 승인으로 해석하지 않는다.
