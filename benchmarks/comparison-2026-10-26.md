## 비교 조건과 한계

- 기본 지침·도구·입력·추론 수준을 같게 하고 조건별 실행 순서를 사례·회차마다 교차했다. 매번 새 임시 스레드와 저장소 밖 작업 폴더를 사용했다.
- 사용 조건에는 선택한 스킬 하나의 정확한 본문과 참조 폴더만 제공했다. 미사용 조건에는 둘 다 제공하지 않았다. 다른 플러그인은 프로세스 설정으로 끄고 예상하지 않은 도구·지침 소스가 없는지 검사했다.
- 소스 `d31c0e7`에서 계획·SKILL/입력 스냅샷과 채점 기준 v1 해시를 실행 전에 고정했다. 지식은 당시 master `a140a6c`와 같다. 뒤의 정책 수정이나 기준 v2를 이 48회에 섞지 않았다.
- 이는 **선택된 스킬 본문·참조의 효과**다. 설치부터 자동 발견·세션 훅까지 포함한 플러그인 전체의 성능은 아니다. CSS에서도 본문을 명시적으로 제공하므로 자동 비선택 시의 비용을 대신하지 않는다.
- 의미 채점은 구현을 진행한 Codex 세션이 수행했다. 독립적인 사람·블라인드 채점이 아니다. CSS 보존은 원문과 직접 비교했다.
- 기존 스킬 개선에 사용한 합성 사례가 포함된다. 새로운 업무·고객 코드·운영 PG/DB·구현 처리량·개발자 작업시간을 평가하지 않았다. 클라우드 모델 ID는 같지만 가중치 버전·seed·서버 부하·캐시 상태를 통제하지 못했다.
- 작은 표본의 체크리스트 충족을 일반 정확도 100%로 설명하지 않는다. 환불 답변 034의 권리 복원 추정과 답변 030의 재호출 조건 표현은 JSON의 별도 관찰에 남겼다.

이는 8종 1회와 환불 1회 추가가 섞인 중단 표본이다. 주 비교와 합산하거나 모델 순위·일반 개선율로 해석하지 않는다. 실패도 JSON에 남겼으며 CSS 예비 시험 4회는 두 비교의 분모에서 제외했다.

## 정책 추정 수정 후 별도 회귀

주 비교의 환불 답변 034는 미제공 쿠폰·포인트 권리 복원 정책을 단정했다. 리뷰 스킬과 부분 환불 규칙에서 할인액의 유지/회수와 권리 복원을 구분하고, 각각 제공된 정책으로 판단하도록 보완했다. `needs-review` 상태와 실제 사업 정책의 미확인 경계는 유지했다.

소스 `2541afa`·같은 `gpt-5.6-sol`·medium에서 원 환불과 신규 합성 정책 사례를 각각 3회씩 사용/미사용으로 실행했다. [12회 입력·답변·판정](results/2026-10-26-policy-followup.json)을 원래 48회와 분리한다.

- 수정 스킬 사용 6/6이 각 사례의 기준을 충족했다. 원 환불 답변 3개 모두 미제공 권리 복원을 금지·의무로 단정하지 않았다.
- 명시한 합성 쿠폰 정책은 두 조건 모두 3/3 충족했다. UNKNOWN 중 보류하고 성공 확정 뒤 정책상 1회 재발급을 허용했다.
- 미사용 1회는 기존 환불의 요청 지문 검토가 빠졌다. 이는 앞서 있던 리뷰 항목의 변동이며, 새 정책 문구의 일반적인 효과로 해석하지 않는다.
- 집중 회귀 동안 로컬 모델 진단도 실행했으므로 이 12회의 시간으로 성능 개선을 주장하지 않는다. 실제 PG·회사 정책 승인도 수행하지 않았다.

## 세션 훅의 로컬 실행 비용

실제 등록된 `node -e …main()` 명령을 매번 새 프로세스로 30회씩 실행했다. 빈 Node stdin 처리와 순서를 교차했고, 모델 진단 프로세스를 종료한 뒤 측정했다. [180개 원시 측정·하드웨어·소스 해시](results/2026-10-26-hooks.json)를 제공한다.

| 훅 동작 | 빈 Node p50 | 실제 훅 p50 | 실제 훅 p95 | 출력 크기 |

| SessionStart | 71.48ms | 79.06ms | 84.30ms | 893바이트 |

| commerce off | 70.45ms | 80.31ms | 83.21ms | 356바이트 |

이 환경의 훅 1회 직접 실행은 p50 약 78~80ms였다. 빈 Node는 런타임 기동 비용을 보는 제어군이며 플러그인 미사용 시 추가 호출 자체는 없다. 클라이언트의 실행 요청·대기, 모델 토큰, RSS, 사용자 전체 작업시간은 이 측정에 포함하지 않는다. 모델 호출 0회이며 세션마다 분리한 임시 상태에 불리언만 저장했다. 재현은 `npm run benchmark:hooks`로 수행한다.
