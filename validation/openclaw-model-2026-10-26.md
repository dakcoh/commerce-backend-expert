# OpenClaw 로컬 모델 적용 후속 — 2026-10-26

**시험한 로컬 구성은 실제 스킬·규칙 적용과 출력 보존을 모두 통과하지 못했다.** [#22](https://github.com/dakcoh/commerce-backend-expert/issues/22)는 미해결로 유지한다. [실제 입력·API 옵션·호출·반환 본문 해시·답변](results/2026-10-26-openclaw.json)을 공개하며, 지침을 명확히 하거나 클라이언트를 설치한 사실만으로 지원 범위를 확대하지 않는다.

OpenClaw 2026.10.7·Ollama 0.40.10·Windows x64·Node.js 24.22.1의 별도 프로필/작업 폴더에서 수행했다. qwen3-coder:30b와 gpt-oss:20b의 실제 로컬 가중치를 썼고 digest를 기록했다. 외부 모델·실제 PG·회사 자료를 사용하지 않았다.

## 네이티브 도구 요청 재생

기존 qwen3-coder CSS 요청을 그대로 재생하되 temperature와 각 쌍의 seed만 지정했다. 32,768 context·4,096 생성 상한·seed 42/43/44에서 다음을 관찰했다.

| temperature | 실제 `tool_calls`의 `read(index.html)` 요청 | 실행한 도구 |
|---|---:|---:|
| 0.7 | 1/3 | 0 |
| 0 | 3/3 | 0 |

이 단계는 provider 응답 형식의 진단이며 파일 읽기 완료가 아니다. 응답 본문에 쓴 JSON을 도구로 복구 실행하지 않았다. 작은 표본에서 도구 요청이 늘었다는 사실로 최종 답변·업무 판단의 합격을 주장하지 않는다. 모델·Ollama·클라이언트 중 하나만 원인이라고 단정하지 않는다.

## 실제 파일 읽기와 원문 보존

정상 설치된 스킬과 별개로 무작위 표식을 파일에 넣어, 모델이 실제 입력을 읽었는지 대조했다. 제어 파일은 정확한 내용만 반환하도록 요청했고 CSS는 두 값 외 원문을 유지하도록 요청했다. 일반 설정을 덮어쓰지 않고, 필요 없는 bundled/custodian 스킬도 별도 프로필에서 껐다.

| 구성 | 제어 파일 | CSS 원문 보존 |
|---|---|---|
| qwen3-coder:30b · temperature 0 · thinking off | 실제 read 1회·오류 0건, 표식에 설명/코드 펜스를 추가 | 실제 read 2회·오류 0건, 원문의 표식 주석 누락 |
| gpt-oss:20b · temperature 1 · thinking high | 실제 read 2회 중 오류 1건 후 내용 일치 | 실제 read 1회·오류 0건, 원문과 불일치 |

제어 파일의 내용 일치와 오류 없이 완료한 읽기는 따로 기록한다. gpt-oss는 오류 후 읽기에 성공했지만 엄격한 오류 0건 조건은 충족하지 못했다. 이 결과를 모든 파일 접근의 불가능으로 설명하지 않는다. 복수 읽기만으로 커머스 문서 비선택을 입증하지도 않는다.

## 스킬·상세 규칙의 실제 반환 확인

gpt-oss:20b·temperature 1·thinking high로 대표 쿠폰, 리뷰 단독 환불, 동시 설치 환불을 실행했다. 일반 AGENTS와 두 가지 라우팅 지침에서 각각 실행한 9개 구성이다. 지침·모델 설정이 달라 일반 실패율로 해석하지 않는다.

- 일반 AGENTS의 쿠폰 사례는 SKILL.md 본문을 반환했지만 상세 규칙은 반환하지 못했다.
- 상대 경로를 작업 폴더 기준으로 읽어 `Optional file not found: …/work/references/coupon/INDEX.md`를 받았어도 native summary는 오류 0건이었다. **도구 오류 0건이 문서 조회 성공은 아니다.**
- 두 라우팅 지침이 실제 provider 문맥에 들어간 것을 확인했지만 리뷰 스킬 선택과 참조 조회는 회복되지 않았다. 필요한 스킬/규칙 본문 반환 조건은 9개 모두 미충족이다.
- 응답에는 미제공 브로커 전제, 단일 인메모리 예제의 한계 오독 등도 남았다. native `ok`나 답변에 등장한 규칙 이름으로 업무 판단을 합격 처리하지 않았다.

모든 실제 도구 호출 수를 native summary와 대조했고, 반환 본문을 제공한 파일과 해시로 비교했다. 선택적 파일 없음·실패·조회 예고는 검증한 문서에 포함하지 않았다. 효과가 확인되지 않은 두 라우팅 지침은 실행 자료에만 보존하고 배포 파일에 추가하지 않았다.

## 재현용 읽기 전용 probe

이미 실행 중인 loopback Ollama와 설치한 클라이언트·로컬 모델을 명시한다. 아래는 재현 예시이며 합격을 보장하는 설정이 아니다.

```bash
node scripts/probe-openclaw-model.js /path/to/openclaw/openclaw.mjs http://127.0.0.1:11434 qwen3-coder:30b 0 off
```

`read-control`은 스킬 없이, CSS는 두 스킬을 제공해 새 폴더에서 실행한다. probe는 실제 native 호출 보고와 무작위 표식/HTML의 원문 일치를 분리하고 실패 시 종료코드 1을 반환한다. 커머스 의미 판단을 자동 채점하거나 입력·정상 사용자 설정을 수정하지 않는다. Node.js 24.22.1 이상이 필요한 클라이언트 검증이며 CI는 네트워크·모델 호출 없이 경계 테스트만 실행한다.

시험용 모델을 메모리에서 내리고 직접 시작한 Ollama·감사 프록시를 종료한 뒤 두 loopback 포트가 닫혔음을 확인했다. 설치 파일·가중치·원문은 무시되는 `output/`에 보관했고 정상 설정·기존 릴리스 태그는 유지한다. 실제 PG·사업 정책 확인은 [#23](https://github.com/dakcoh/commerce-backend-expert/issues/23)에서 별도로 남는다.
