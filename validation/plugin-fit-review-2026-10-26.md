## 실제로 확인한 장점

- 문서 스킬에는 자체 서버·API 키·런타임 설치가 필요 없다. 훅만 Node.js를 사용하며, 스킬만 설치하는 경로도 유지한다.
- 대표 스킬과 리뷰 스킬이 각각 독립 설치된다. 리뷰 단독에는 없는 형제 문서가 있다고 가정하지 않으며, 상세 규칙을 전체 주입하지 않는다.
- 70개 규칙의 적용 조건·예외·전제·검토 상태를 구조화했다. 미확정 환불이나 할인 유지와 권리 복원의 구분처럼 실제로 오판하기 쉬운 업무 경계가 있다.
- 형식·경로 검사, 실제 조회/답변 공개, 실패한 실행의 보존을 함께 운영한다. 모호한 효과 주장보다 결과를 재검토하기 쉽다.
- 훅은 켜기/끄기 상태만 저장하며 외부로 대화를 전송하지 않는다. 기존 격리 설치·제거와 로컬 테스트 44개, 병합 소스 CI 6개 환경이 통과했다.

## 실용성을 제한하는 점

1. **추가 품질 이득을 입증하지 못했다.** [명시적 스킬 제공/미사용 48회 비교](../benchmarks/comparison-2026-10-26.md)에서 두 조건 모두 사전 기준 24/24였다. 스킬 사용 시 쌍별 시간 비율 차이 중앙값은 +2.5%, 총 입력 토큰은 +65.5%였다. 같은 AI가 의미를 채점했고 익숙한 합성 사례가 포함돼 있다. 일반 정확도·개발 시간·청구 비용으로 확대할 수 없다.
2. **문서가 많아도 모델이 읽고 적용한다는 보장은 없다.** [OpenClaw 실제 기록](openclaw-model-2026-10-26.md)에서 조회 예고, optional missing-file 응답과 native 오류 0건이 문서 본문 반환을 뜻하지 않았다. 도구 호출 형식과 환불 판단 오류도 별개다.
3. **근거 성숙도가 균일하지 않다.** 51개는 `active`·`project-guidance`이고 검토자/검토일이 `not-recorded`다. 나머지 19개는 외부 근거에 대한 AI 검토 기록이 있지만 `needs-review`를 유지한다. active를 검증된 규칙 수나 사람의 운영 승인 수로 표시하면 안 된다.
4. **고유한 사업 맥락의 효과는 미측정이다.** 공개 규칙은 모델의 일반 지식과 겹친다. 회사 고유 계약·정책·장부를 적용하는 경우와 처음 보는 코드의 오탐/미탐을 측정해야 추가 가치를 판단할 수 있다.
5. **훅의 편의에도 실행 비용이 있다.** [180개 직접 실행 측정](../benchmarks/results/2026-10-26-hooks.json)의 p50은 약 78~80ms다. 일반 요청은 출력 0바이트지만 훅 프로세스 자체는 실행된다. 이 값은 호스트 전체 대기시간·모델 시간·RSS를 포함하지 않는다.

검토에서 후속으로 개선할 지점도 찾았다. 예를 들어 [카탈로그 규칙](../skills/commerce-backend-expert/references/commerce/commerce-catalog-model.md)은 상품·SKU·판매 조건을 구분하는 취지에 더해 세 식별자/테이블의 물리적 분리까지 일반 지침으로 읽힐 수 있고 적용 제외 조건이 비어 있다. 단일 판매자·채널·옵션 없는 작은 카탈로그의 논리적 책임 구분과 실제 테이블 분리 필요성을 나눌 여지가 있다. 이는 문구 검토에서 찾은 오탐 위험이며 이번 실행에서 모델의 실제 오탐으로 재현한 결과는 아니다. 근거 없이 규칙 51개를 한꺼번에 다시 쓰거나 검토 완료로 표시하지 않았다.

검토 기준 소스의 대표 SKILL.md는 5,250바이트, 리뷰는 5,669바이트이며 규칙 본문 70개는 총 231,308바이트다. UTF-8 원문 크기이며 토큰 수가 아니다. 경로 보완 당시 대표 스킬은 5,533바이트였다. 이후 [별도 토큰 최적화](../benchmarks/token-optimization-2026-10-26.md)로 대표 스킬은 3,859바이트를 채택했으며 리뷰는 5,669바이트를 유지했다. 현재 구조에서 전체 지식 폴더를 매번 제공하도록 바꾸거나 클라이언트별 지식 복제본을 늘릴 이유는 없다.

## #22 경로 보완의 실행 근거

OpenClaw 2026.10.7·Ollama 0.40.10·gpt-oss:20b 고정 digest·thinking high·temperature 1·context 32,768·생성 상한 4,096에서 실행했다. 별도 작업 폴더·프로필과 읽기 도구만 사용했다. [6회 입력·답변·실제 옵션·호출·반환 본문 해시](results/2026-10-26-openclaw-base-dir.json)를 제공한다. 기존 48회 평가나 9개 사업 사례의 분모에는 합산하지 않는다.

| 조건 | 기존 본문 | 경로 예시 추가 후보 |
|---|---|---|
| 자연어 쿠폰 질문, seed 42/43 교차 순서 | 2회 모두 도구 호출 0·스킬 미조회 | 2회 모두 도구 호출 0·스킬 미조회 |
| 같은 질문 앞에 스킬 전체 읽기 명시, seed 42 | SKILL 본문만 반환, 상대 경로의 색인·규칙 조회 실패 | SKILL·쿠폰 색인·발급 규칙의 실제 본문 반환 확인 |
| 명시적 조건의 도구 오류 | `optional:false` 인자 검증 오류 1건 | 같은 인자 오류 1건 후 잘못된 옵션을 빼고 조회 회복 |

명시적 조건의 두 실행은 모두 native ok였고 도구 호출도 각 4회였다. 차이는 실제 반환된 문서였다. 후보의 답변은 규칙 조회 뒤에도 오류가 남았다.

- 입력에 1인 1매 정책이 없는데 `(campaign_id, user_id)` UNIQUE를 필수로 제시했다. 읽은 규칙은 1인 1매일 때 가능한 키와 회차/1인 N매의 구분을 명시한다.
- Redis Lua 오류 뒤 스크립트 내부의 재실행으로 롤백하고 DECR를 다시 수행한다는 잘못된 복구를 제시했다. 읽은 규칙은 오류 시 앞선 쓰기가 남을 수 있고, 첫 쓰기 전 검증과 부분 반영 대사가 필요하다고 명시한다.

따라서 **후보의 문서 반환 조건 1회 충족과 업무 판단 통과는 다르다.** 위 의미 검토는 구현 AI의 후속 관찰이며 독립 사람·블라인드 채점이나 사전 기준의 통계적 개선율이 아니다. 같은 모델·seed도 서버와 캐시 상태까지 완전히 통제하지 못했으며 자동 선택 실패의 원인을 모델 하나로 확정하지 않는다.

이 절에서 평가한 변경은 대표 스킬의 경로 예시 두 줄이며 이후 압축 실험과 별도다. 다른 클라이언트에서는 SKILL.md가 있는 폴더를 기준으로 상대 링크를 해석하도록 유지했다. 도구 응답 JSON의 강제 실행, 정상 설정·파일 접근 범위 변경, 전체 문서 주입은 추가하지 않았다. 모델을 언로드하고 직접 시작한 Ollama·감사 프록시·두 loopback 포트를 종료한 기록도 JSON에 남긴다.

## 다음 판단에 필요한 증거
