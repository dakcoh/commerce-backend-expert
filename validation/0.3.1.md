# 0.3.1 검증 기록

2026-10-24, Windows·Node.js 24.22.1·npm 11.19.1·Codex CLI 0.153.2·Claude Code 2.1.114에서 확인했다. PR #17(`28d1540`)까지의 릴리스 후보 검증이며 태그 생성·공개 릴리스 완료를 뜻하지 않는다. 이후의 규칙·클라이언트 검증은 [후속 기록](followup-review.md)에서 구분한다.

## 지식 검토

`webhook-handling`은 [토스페이먼츠 v2 웹훅 문서](https://docs.tosspayments.com/guides/v2/webhook)의 응답 코드·제한시간·재전송 범위를 확인했다. 특정 PG의 조건을 모든 PG에 확대하지 않으며, 짧은 동기 처리 허용과 긴 후처리 분리는 프로젝트의 설계 판단이다.

`concurrency-distributed`는 [Redisson Lock 문서](https://redisson.pro/docs/data-and-services/locks-and-synchronizers/#lock)의 획득 결과·lease·watchdog·소유 스레드 해제를 확인했다. 관련 재고 체크리스트·결제 원장 지침·리뷰 스킬과의 설명도 비교했다. 주문자·결제자·수령자 구분은 `commerce-customer-identity`의 적용 조건과 함께 확인했다.

두 규칙의 AI 문서 검토자·날짜·범위를 기록했다. 실제 DB·PG·Redis 및 운영 계약 검증은 없으므로 `needs-review`는 19개 그대로다. AI 문서 검토를 사람의 승인이나 운영 안전성 인증으로 간주하지 않는다.

## Codex 훅

실제 배포 구성의 두 훅을 격리 프로필에 설치한 뒤 `/hooks`에서 검토·신뢰했다. 신뢰 우회 옵션이나 진단용 기본 훅은 사용하지 않았다. 이후 같은 프로필의 app-server로 다음 절차를 수행했다.

1. `hooks/list`에서 두 훅의 `trusted` 상태와 후보 0.3.1 설치 경로를 확인한다.
2. `thread/start` → `turn/start`로 시작·명령·일반 프롬프트를 전달한다. 클라이언트의 `hook/completed`와 반환 문맥을 확인한다.
3. 프로세스를 종료·재시작하고 같은 대화를 `thread/resume`으로 재개한다.
4. `thread/compact/start`로 실제 수동 압축을 실행하고 다음 요청에서 SessionStart 문맥을 확인한다.
5. 프로젝트·세션을 바꿔 상태 격리를 확인한다.

모델 요청은 localhost의 결정적인 Responses 응답 대역으로 보냈다. 대역은 고정 답변만 반환하고 명령이나 도구를 실행하지 않는다. 훅 호출과 요청 문맥 전달은 실제 Codex의 동작이지만, AI의 스킬 선택·추론 품질을 검증한 시험은 아니다. 인증 정보 복사·원격 모델 호출은 없었다.

| 확인 항목 | 확인 결과 |
|---|---|
| 시작 | ON과 설치된 두 스킬의 경로 |
| off → status | OFF 유지 |
| 일반 프롬프트·부정문 | 추가 문맥 없음, 상태 변경 없음 |
| 프로세스 재시작·재개 | 같은 프로젝트·세션은 OFF 유지 |
| 실제 수동 압축 | 다음 요청에 OFF 문맥 전달 |
| on | ON과 스킬 경로 복원 |
| 다른 프로젝트·세션 | 기본 ON, 원 프로젝트의 OFF 유지 |

## Claude 훅

기존 후보 `63ab00d`의 오프라인 테스트 37개, 새 설치, 실제 v0.3.0 → 0.3.1 갱신·재설치·제거의 회귀 검사에서 실패가 없어 다음 작업인 Claude 실동작 검증을 진행했다. 같은 커밋의 원격 CI 6개 조합도 성공 상태임을 확인했다.

[실행 스크립트](../scripts/smoke-claude-hooks.js)는 배포용 manifest·스킬·세션 훅만 복사하고, 별도의 `CLAUDE_CONFIG_DIR`와 임시 폴더를 사용한다. 기본 진단 훅을 추가하지 않으며 사용자 프로젝트 설정·인증 정보·플러그인을 가져오지 않는다. `--plugin-dir`로 두 스킬과 훅을 로딩하고 `--tools ""`로 모델 도구를 끈다. 임시 키와 localhost의 고정 Messages 응답만 사용하므로 원격 모델 호출은 없다.

```bash
node scripts/smoke-claude-hooks.js /absolute/path/to/claude
```

Claude Code 2.1.114로 12개 실제 CLI 실행을 확인했다. 시작, off/status/on, 인용·부정문의 무출력, 프로세스 종료 후 재개, 실제 `/compact`의 `compact_boundary`와 `SessionStart:compact`, 압축 뒤 OFF 문맥 전달, 새 세션·새 프로젝트의 ON 및 원 세션의 OFF 유지를 assert로 비교한다. 초기 출력에서 두 스킬이 발견되는 것도 확인했다. CLI 이벤트·요약은 `output/claude-hooks-*`에 남기며 기본 자동 테스트 수에는 합산하지 않는다.

Claude의 마켓플레이스 설치, 실제 모델의 문서 적용, 자동 압축·다른 버전의 동작은 이 검사에 포함하지 않는다.

## 남은 범위

후보 커밋이 바뀌면 원격 CI를 다시 확인하며 공개 배포도 별도 완료 확인이 필요하다. Cursor·OpenClaw 실제 실행, 자동 압축·다른 Codex/Claude 버전, 실제 DB·PG·Redis, 반복·미사용 대조군 평가는 미검증이다.

English: The candidate was checked on Windows with Node 24.22.1, Codex CLI 0.153.2, and Claude Code 2.1.114. Actual client lifecycle calls used deterministic local model responses, including twelve repeatable Claude checks. This verifies hook execution and context delivery, not model quality. The two changed high-risk rules received scoped AI document reviews and retain needs-review. Other clients, live systems, remote candidate CI, and publication require separate evidence.
